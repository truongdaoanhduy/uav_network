# V3 session continuation and relay evaluation

User approved the preceding W&B audit recommendations and requested execution on 2026-10-20. This work implements that accepted scope in the existing pipeline.

Goal: preserve unfinished V3 missions across training sessions, expose truthful completion/logging status, and test whether search/relay/power can complete the mission within the existing energy/network constraints.

Constraints: do not change uav_network/algorithms or scientific environment/network/reward equations; keep original training seed44,4096env,20000episode target,max_steps1800 for future Kaggle runs,1MBreport/3MBbuffer,35targets/25obstacles. Evaluation controllers/ablations are labeled and never presented as learned baselines. New behavior must be backward compatible with old version3 checkpoints, explicitly labeling legacy environment-reset resumes. Do not create or rotate accounts to bypass quota. Test on CPU first; any available CUDA validation uses one controlled session with prechecked quota and pinned source.

Resume design: WarpVectorEnv snapshot_state()->dict and restore_state(payload)->observation dict. Capture every world array including packet queues, PHY/MAC/session timers, geometry,battery,mission counters and simulator RNG, plus active seeds/action-generator state. Synchronize before copying and restore only at a non-waiting collection boundary. Validate exact array set,shape,dtype and scenario/num_envs compatibility before mutating the vector. Persist per-env accumulated returns,lengths,seeds and next_seed along with the simulator snapshot inside existing training checkpoint payloads. BASE and PQL restore this state and do not reset/reseed active worlds. Old checkpoints remain supported as explicit environment-reset resumes. Policy-only evaluation checkpoints stay small.

Continuation design: positive completed episodes remains valid legacy progress. A time-budget segment with zero new episodes can continue only when it saved an exact environment state, advanced global transitions, published a new immutable full checkpoint, and matches parent expected episode AND global-step prefixes. Reject no-progress/contradictory/missing-state inputs. W&B labels session stop versus full episode-budget completion, and captures console output. Successful final completion alone triggers separate CPU visualization.

Evaluation design: reuse existing evaluation and privileged feasibility oracle. Provide paired learned/direct-only/fixed-power controls with identical scenario,checkpoint,seeds. Controls change only evaluated communication actions; preserve movement and physical channel. Full35-target feasibility is privileged and explicitly not a learned-policy baseline. Persist per-episode records,aggregate discovery/GCSdelivery,fullsuccess,report direct/relay counts,power diagnostics,J/delivery,battery and traces. Missing denominators stay null,not zero. Resume audit outputs without silently overwriting incompatible protocols. No curriculum or reward retuning.

Verification: failed-before-fixed deterministic split-world roundtrip and zero-episode continuation tests, BASE/PQL integration,legacy checkpoint compatibility, malformed snapshots/no-progress rejection, paired evaluation seed/route/power controls, frozen algorithm hashes, full existing CPU suite and CUDA checks if compute is available. Full long-training completion is reported only when exact episode budget is reached.

User amendment2026-10-20: future Kaggle runs use max_steps=1800. Old2000-step checkpoints retain their saved evaluation horizon. Exact full-state continuation across this scenario change is incompatible and must not be silently relabeled. Create a separate1800-step comparison profile; preserve old files/evidence.
