# MATD3 no-oracle V9: W&B visualization parity and deeper Hugging Face forensics

Verified against **exact source** of historical Kaggle notebook `therwed/notebook5051433b29` / W&B run `18d756ef` and the V9 notebook on 2026-11-22. This is an implementation and CPU+mock-transport verification; there is **not yet a production E4096 T4×2 20,000-episode V9 run**, and live W&B workspace saving and Hugging Face uploading have not been verified on Kaggle.

## Historical W&B records (queried from real run, not inferred)

W&B `truongdaoanhduy-uit/uav_search_target/18d756ef` returned: **33,954 total history rows**, `episode/return` **626** points, `training/discovery_rate_percent` **626**, `training/gcs_delivery_rate_percent` **626**, `episode/index` **939** (includes cohort rows), `train_progress/discovery_rate_percent` **6,726**, `train_loss/critic_loss` **6,695**, and `gpu_eval_periodic/checkpoint_global_step` **69**. The historical run log cadence therefore corresponds to one episode observation per **32 completed episodes**, plus **64-episode average** cohorts, and time-dense global-transition-based reward/optimizer/mission series. Do not interpret the vector-step series as one unique episode per x tick.

## V9 W&B implementation

- **Training:** original exact scalar keys for episodic return, search, GCS delivery, discovery/delivery AUC, coverage/AUC, mission success, capped completion/delivery times, energy and packet PDR, plus real source `episode/index`. Compact episode logging interval **32**, episode mean/tradeoff cohort interval **64**, fixed to match the *historical sampling mechanism*. Missing metrics (e.g. energy/delivery for an episode with zero GCS deliveries) stay missing; no fabricated zero.
- **Vector steps:** real `train/step_reward_mean`, `train/step_reward_std`, `train_progress/*`, `train_loss/*` on actual `global_step` generated by MATD3 training, including loss/gradient/noise/progress. Never attach a fabricated episode ID to an optimizer update.
- **Validation100:** real `gpu_eval_periodic/*` keyed to immutable checkpoint step and exactly **100 shared held-out seeds/checkpoint**. Best selected using validation only. **Final Test4000** is one independent held-out summary `gpu_final/*`, never mixed into training convergence. 2 GPU worlds/policy batch for eval (200 worlds/GPU) is conservative and **not the 81×100 batch of historical notebook**; counts/seeds/evaluation protocol remain as intended.
- **Native W&B workspace** `wandb_dualaxis_baseline_workspace`: **48 real scalar panels in five named sections**: 14 Episode, 7 Vector-Step, 7 Optimizer, 11 Validation, 9 Final Test. Notebook starts its creation asynchronously after credentials and source initialization, writes the generated URL to `wandb_dual_axis_view_<runid>.json`, and prints/locally logs a warning if the remote API cannot create the view. This is a **new per-run saved workspace**, not a modification of the user's historical W&B workspace. No PNG/SVG image upload is substituted for actual W&B chart points. The saved view must be verified on a live Kaggle run.
- **Runtime:** live W&B run id, actual episode budget, real phase labels (`awaiting_gpu_validation`, `gpu_validation`, `fullflow_complete`), runtime heartbeat and final GCS metrics are emitted to W&B summary. Output line visibility in Kaggle UI and saved dashboard usability still depend on the platform and authentication.

## V9 Hugging Face contents and deep sampling

- Historical HF run `18d756ef` contained **17 raw diagnostic source types** in 169 immutable archive parts. V9 whitelists **19 types**, preserving all historical types and adding `failure-events.jsonl` (sanitized traceback/context) and `evaluations/events.jsonl` (when written). The original 17 types include individual episode outcomes, vector-step reward/progress/optimizer, warnings, root-cause timeline, replay minibatch, learner gradient layers, mission/PHY/network, sampled pre/post Warp states, integrity and resource/health evidence, and thread stacks. Some optional files may not exist in every run.
- The V9 Kaggle notebook **enables** `UAV_DIAGNOSTIC_STORE=huggingface_public`, `UAV_FAST_TRAINING=false`, verifies remote public read-back SHA256, and uses Kaggle Secret `HF_TOKEN`. Compressed TAR parts default to 8 MiB raw payload, regularly sampled and flushed at training completion/failure; failed parts are retained for retry and W&B storage status records incomplete uploads. It never silently declares a failed transfer as successful.
- To make the *selected-world transition trace* deeper than the historical single-world, 64-vector-step default, V9 notebook now uses `UAV_FORENSIC_WORLD_IDS=0,1`, `UAV_FORENSIC_STRIDE=32`, `UAV_FORENSIC_FULL_BELIEF=true`, and per-trace raw-file cap **384 MiB**. Each sampled frame can include Actor local observation, centralized Critic state, pre/post Warp arrays, actual action, policy heads, obstacle/target positions for offline scoring, power/radio/safety, reward decomposition and learner/replay metrics. The snapshot arrays are **for forensic analysis**, not Actor observations. The default *does not* log all 4096 worlds each timestep (that could cost terabytes). Increased sampling may affect throughput; this setting is user-adjustable.
- **Post-Train Eval/Test:** separate verified HF `post-eval-forensics` TAR parts include every `eval_XXXX.json`, `validation_results.json` and CSV, selected `best.json`, `report.json`, `final_test.json`, and **pre-aggregation per-T4** `final_test_gpu0_*_*.json` and `final_test_gpu1_*_*.json` (newly found omission, fixed RED → GREEN). Worker-specific seed shards preserve the local packet counters and per-target report/timestamps for debugging either GPU. Files over 8 MiB are transmitted as verifiable byte slices with original file names, source SHA256, and offsets, retrying without data loss. Partial `.tmp` JSON is never uploaded.
- Training diagnostics are not equivalent to complete per-UAV steps for every E4096 world. Raw notes can contain map ground truth used for scientific scoring/forensics; **only** policy inputs obey the no-oracle requirement.

3. `tests/test_matd3_v9_post_eval_hf_forensics_20261122.py`: RED exposed omission of `final_test_gpu{gpu}_{start}_{stop}.json`; GREEN ensures both GPU shard files enter verified archive, excludes incomplete worker `.tmp`, preserves raw Eval/Test files and retries network failure.
4. `tests/test_matd3_v9_large_eval_archives_20261122.py`: byte-exact reconstruction, bounded slice size, duplicate-free continuation on retry and fail-closed source mutation.
5. Prior full functional suite completed **1,627 passed / 105 skipped / 1,121 subtests** before these W&B/HF-specific additions; latest complete full-suite result is recorded separately. A separate structural-style test has 7 inherited >500-line deviations, and no new implementation should increase that count.

## Accuracy limitations

The W&B line graphs require a real uploaded V9 run to display. A passing fake-SDK test **does not prove** W&B cloud accepted the new saved view or Hugging Face uploaded all parts. Users should check the run ID in W&B, `storage/hf_verified_uploaded_files`, `storage/hf_incomplete`, `storage/eval_hf_published_files`, and download/verify the final archive manifest. No DS-map fusion at GCS or 3D obstacle reconstruction is introduced here.
