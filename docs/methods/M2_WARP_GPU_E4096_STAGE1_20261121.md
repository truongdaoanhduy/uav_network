# M2 1000 m target belief F/E/U: Warp GPU E4096 Stage-1 audit

**Scope:** 1000 m world, 25 m target-belief grid cell, 40×40 cells, 6 UAV local 2D target maps plus 1 GCS 2D target map per world. Physical UAV flight and obstacles may be 3D, but there is **NO 3D map reconstruction or 2D obstacle belief map**. External reference: Zhang et al., IEEE TIV 2024, DOI 10.1109/TIV.2024.3352581. This GPU module implements numerical DS map primitives from the **user's correlated conditional-evidence extension**, not the paper's fixed `mf=me=0.8` formula by itself.

## GPU primitives implemented

- `uav_network/environment/gpu/m2_mass_projector.py::m2_project_mass` launches one Warp thread per `(world,node,ground_cell)`. Its two inputs are **non-negative accumulated conditional LLR supports** `A`,`B`, computed after source-provenance deduplication and shared-latent sensor likelihood updates. It calculates stable normalized 2D target masses: `mF = expm1(A)/(expm1(A)+expm1(B)+1)`, `mE = expm1(B)/(...same...)`, `mU = 1/(...same...)` via logsumexp to avoid overflow and conflict underflow.
- `m2_apply_sparse_llr` applies already validated unique signed conditional LLR event deltas into `(world,node,cell)` support arrays with `warp.atomic_add`. Positive and negative supports remain separate. It does **not** synthesize sensor readings, deduplicate event IDs, compute correlated latent conditionals, or invent packet reception.
- Output remains 2D target-only F/E/U; no obstacle geometry is mapped.

## Hardware and validation status

Account 1 Kaggle GPU quota was checked through a locally selected credential with no token disclosure. The Kaggle private GPU notebook URL is `https://www.kaggle.com/code/longlonthiu/m2-target-belief-2d-warp-gpu-e4096-parity-smoke`.

- **Version 1** verified complete on both Kaggle Tesla T4 GPUs, NVIDIA Warp 1.18.0. Both tested a dense 4096×7×1600 map = 45,875,200 cell/node/world entries per GPU (approximately 917,504,000 bytes for five float32 arrays, excluding allocator overhead). Mass sums were normalized; per-GPU small random/extreme parity against native reached max absolute error about `2.30e-7`. GPU0 4096-world uniform case ~9.7ms after compilation; GPU1 ~6.6ms. **These times are single kernel projection times, not environment rollout or training throughput.**
- **Version 2** adds random supports over the entire E4096 tensor (and small native parity samples) to avoid benchmarking only uniform support; status logged separately after completion.
- **Version 3 source staged** adds sparse atomic conditional LLR event support updates; first tested on CPU Warp and intended for a later GPU validation. Do not call this validated on GPU until the Kaggle version actually reports COMPLETE and its artifact is inspected.
- Local CPU Warp tests of mass projection include zero mass, long conflicting positive/negative supports, randomized 2D Native DS map parity with out-of-order original events, and sparse support with repeated cell indices. CPU tests are **not** substitutes for GPU verification.

## Not yet integrated: do not launch misleading training

The original Warp `WarpVectorEnv` (under `uav_network/environment/gpu/vector.py`) continues to run the **older Bayesian sensor and target-id-oriented radio behavior**. It does **not** implement the same M2 packet events, shared latent conditional evidence, cooperative SPRT, GCS source-provenance map delta, or two-way relay. **Never set `m2_enabled=True` and use the legacy WarpVectorEnv**. The existing `make_vector` guard must remain until a full explicit Warp M2 backend is implemented with episode reset, actor observation ABI, GCS map parity, bounded event storage, and native-vs-Warp tests under identical seeded scenarios.

A completely correct native M2 event-GCS flow remains tested on CPU. CUDA E4096 numerical DS primitive tests do **not** establish learned MATD3/MASAC convergence or correctness of a full Warp+UavNetSim simulation. Report these as distinct phases in any research presentation.

## Suggested next validation gates, not completed here

1. Generate noisy correlated sensor events on GPU and validate their conditional likelihoods against CPU reference for identical RNG streams and partial FOV/occlusion; account for ambiguous sensor calibration.
2. GPU bounded per-environment event stores with immutable source IDs and duplicate suppression, plus sorted per-cell conditional likelihood update and out-of-order replays; avoid an O(E4096×total_events) global replay.
3. GPU packet route/PHY/MAC state with real drop, ACK, TTL, delay and return GCS `MAP_DELTA`; compare against Native UavNetSim via exact event trace parity.
4. Integrate M2 Actor 5D + destination categorical, M2 observation/state, episode reset, current reward and true GCS delivery metrics; test learning updates on GPU and avoid truth leakage.
5. Seed-matched 4096-world stress on 2×T4, VRAM checks, performance, and periodic validation for MATD3/MASAC. An E4096 memory estimate for dense mass arrays alone is ~0.92GB per GPU, not total simulation footprint.
