## Fatal error and its precise timing

- **Training finished 20,000/20,000 episodes**, 28,556 MATD3 optimizer updates, 29,368,320 environment transitions, 7,170 vector steps, mean throughput ~2,100 transitions/s.
- W&B `failure.json` and Kaggle `output.log` show the **single confirmed fatal exception** was a `ValueError` in `uav_network/experiments/tracking.py::_checkpoint` invoked by `tracker.complete()` at the very end of the training call (`training.py` line 738). Message: `Training-only requires a validated best checkpoint`.
- The original Kaggle job had `training_only=true`, `one_session_train_eval_test=true`, `tracking.deferred_gpu_eval_enabled=true`, `tracking.deferred_gpu_eval_keep_all=true` and `tracking.online_gpu_eval_enabled=false`. **Validation100 is intentionally deferred**. Calling `_checkpoint(final=True)` from `tracker.complete()` before the deferred GPU validation produces a logically impossible condition: the required best Actor does not yet exist.
- The failure occurred **before** `uav_network.experiments.one_session` could evaluate snapshots. It was **not** a MATD3 training NaN, OOM, Kaggle 1 MiB source limit, GPU power/runtime fault, or source size issue. The observed status `FAILED` is the appropriate failure of the orchestration stage, not evidence that training was aborted at an early episode.
- Original `summary.json` from the exact Kaggle job survived: `episode_budget_complete=true`, `tracking_status=failed`, `tracking_error_type=ValueError`, and `deferred_gpu_evaluation.snapshot_count=134`.

1. **Atomic deferred training handoff** (`uav_network/experiments/tracking.py::complete`): when `UAV_TRAINING_ONLY=true` and deferred GPU evaluation is configured, validate the recovered Actor archive and complete manifest, mark `fullflow/train_complete` and `checkpoint_selection.kind=pending_gpu_validation`, and return without uploading a nonexistent best Actor. Keep the strict validated-best requirement in `_checkpoint` for the *actual* post-validation publisher. Preserve nondeferred behavior and fail closed on incomplete archive.
2. **Restore native W&B training outcome series** (`training_mission_metrics.py`): real `episode/index` and source terminal records for `training/discovery_rate_percent`, `training/gcs_delivery_rate_percent`, target counts, mission success, capped discovery and delivery times, discovery AUC, delivery AUC, energy, PDR, coverage, and coverage AUC. No pseudo-target identities, invented missing values or static PNG uploads. `CompletedMissionWindow(64)` emits real aggregated cohort means and `EpisodeReturnWindow(64)` logs genuine completed episodic returns.
3. **Restore dense vector-step optimizer/reward/mission metrics** via `OnlineTracker.step_reward` using existing native `PerVectorStepRewardJournal`, `PerVectorStepMissionProgressJournal` and `PerVectorStepOptimizerLossJournal`. Logging uses `global_step` reflecting E4096 actual collection transitions, and never attaches fabricated `episode/index` to individual optimizer rows. In Kaggle, `UAV_WANDB_PLOTS_ONLY=true` restricts W&B history to native chart scalars, while HF receives full forensic records.
4. **Original real coverage AUC**: added `WorldState.coverage_first_seen_step`, `coverage_auc_weight_sum`, Warp `atomic_min` first seen across all UAVs, and exact normalized time-integral `sum(max_steps-first_seen)/(max_steps*grid_n²)`. Tested overlapping UAV observations for no double-counting. These fields are observations-only for paper metrics and do **not** feed policy/critic/reward.
5. **Public forensic HF archive**: `UAV_DIAGNOSTIC_STORE=huggingface_public` and `UAV_FAST_TRAINING=false` turn on the `CompressedDiagnosticArchive` and SHA256 readback-verifying `PublicHubDiagnosticUploader` to the public dataset. A half-written file is never mistaken for a finished result. Unit tests verified sequential chunks, incomplete JSON exclusion, and retried upload. No original V7 diagnostics are invented retroactively.
